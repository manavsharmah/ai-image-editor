# Task: m2b-tests — Test setup and M2 regression tests

Goal: automated tests exist, so later phases can be verified.

Read `AGENTS.md` and follow the phase workflow. State a short plan before
coding. Work on the current `m2b-tests` milestone branch, make small commits,
and never push, merge, or deploy. Do not start another phase.

## Current code

- Root `package.json` has `dev` and `deploy` scripts, but no test runner.
  `npm run dev` starts the existing API workspace's Wrangler development server.
- `apps/web/index.html` provides `#file`, `#view`, `#status`, `#panel`,
  `#format`, and `#download`. The editor runs at `/`.
- `apps/web/js/editor.js` generates controls from the schema and exports
  `setLook()`. Opening a photo resets the look. Downloads use the renderer's
  full-resolution export path.
- `apps/web/js/renderer.js` exports `createRenderer()` with `setImage()`,
  `render()`, and `exportBlob()`. Preview rendering is scheduled on the next
  animation frame; export draws synchronously before encoding a Blob.
- `apps/web/shared/look-schema.js` exports `SLIDERS`, `BANDS`, `CHANNELS`,
  `DEFAULTS`, `clampLook()`, and `validateLook()`.
- `apps/web/js/photo-file.js` checks file signatures and returns a friendly
  unsupported-file message. No application code currently sends photo data.

## Files and scope

- `package.json`, `package-lock.json`: install Playwright and add test scripts.
- `playwright.config.mjs`: browser configuration and development web server.
- `tests/helpers/images.mjs`: deterministic synthetic image generation,
  browser-side PNG decoding, and pixel measurements.
- `tests/helpers/editor.mjs`: shared upload, schema lookup, slider interaction,
  readiness, and download helpers where useful.
- `tests/m2-rendering.spec.mjs`: default look, exposure, and red saturation.
- `tests/m2-upload.spec.mjs`: non-image rejection and recovery.
- `tests/m2-privacy.spec.mjs`: network observation during local photo editing.

Keep all fixtures and test utilities under `tests/`, outside public assets.
Do not edit `apps/`, the roadmap, pipeline, or earlier task files. Do not add
AI, reference matching, statistics, mobile polish, or other product features.
Do not expand this into a general test suite for every M2 feature.

## Implementation steps

1. **Set up the runner.** Add `@playwright/test` as a root development
   dependency and make `npm test` run the complete suite. Use `.mjs` files
   without changing the package's module type. Configure `testDir` as
   `tests/`, a headless Chromium project, and `webServer.command` as exactly
   `npm run dev`, with the matching local Wrangler URL and `baseURL`.
   Have Playwright wait for the editor server before testing. Install the
   Chromium browser needed by the suite. WebGL2 must actually work; an
   unavailable renderer must fail with a useful diagnostic, not skip tests.
   Place generated reports and results in an ignored location such as
   `.pipeline/`, without changing `.gitignore`.

2. **Prepare deterministic measurements.** Generate small opaque PNGs in
   the browser using canvas: an asymmetric image with varied colors and
   brightness, a midtone image, and separate moderately saturated red and
   blue patches. Use no external photos, fonts, or network fixtures. Keep
   the source RGBA pixels as the independent expected data. Decode PNG
   downloads back to pixels for comparisons; do not compare encoded file
   bytes, JPEG output, or screenshots of the page. Await upload completion
   and download events rather than using fixed sleeps. Import the schema
   in the browser to obtain slider names, limits, defaults, and labels;
   select exposure by its `lightStops` effect and the red saturation slider
   by band/channel metadata. Do not duplicate slider names or ranges.

3. **Test the default look.** Open the asymmetric PNG through `#file`, wait
   until the editor is ready, and download a PNG with the default look.
   Assert that dimensions and pixel positions match the source, including
   different top and bottom regions so a vertical flip cannot pass. Allow
   at most two intensity levels per RGB channel for GPU rounding, and
   require opaque alpha to remain opaque. Compare against source pixels,
   never a baseline generated by the renderer being tested.

4. **Test exposure and selective saturation.** Capture default output,
   then change only the exposure control to a positive, schema-derived,
   in-range value. Assert that mean RGB brightness increases by a meaningful
   documented margin on the midtone fixture. In a separate test, start
   from defaults and lower only red saturation toward its schema minimum.
   Measure mean absolute RGB change inside each patch, excluding borders.
   Require a substantial red change (for example, at least 10 intensity
   levels), a blue change within rounding tolerance (at most two), and red
   change at least five times blue change, using a small denominator floor.
   Use actual range input events so the controls and renderer are exercised
   together. Document thresholds; do not loosen them merely to hide a failure.

5. **Test non-image rejection.** Submit a text payload as a non-image file
   through the file input, bypassing the chooser's accept filter. Assert a
   visible, friendly unsupported-file message in `#status`, no uncaught
   page error, and no enabled download without a photo. Then open a valid
   synthetic PNG and confirm the editor becomes usable, proving rejection
   did not crash it. Keep HEIC, tiny-image, and huge-image coverage for
   `m5-polish` as specified in the roadmap.

6. **Test that photos stay local.** Register browser-context network
   observation before navigation, then load the editor, open a synthetic
   photo, adjust a slider, and download locally. Observe all outgoing HTTP(S)
   requests, including URLs, methods, headers, and binary request bodies;
   do not restrict inspection to `/api/*` or JSON. Permit only the known
   same-origin static resource requests with no bodies and no image-bearing
   query strings during this current M2 flow. Any unexpected destination,
   upload, or image bytes/base64 in a request must fail the test. Account for
   normal static loads explicitly rather than disabling network observation
   after startup. A local Blob download is not an HTTP upload. Do not mock
   the renderer, upload handler, or network APIs to manufacture a pass.

7. **Follow the review and test stages.** The Builder establishes the test
   setup and reusable helpers. After review, the Test-spec writer maps the
   four regression behaviours above to `.pipeline/test-spec.md`; the Test
   writer implements or completes the tests for every item within its
   allowed files. Keep pure helper logic simple; if separate `node:test`
   tests are needed, include them in `npm test` and keep their discovery
   separate from Playwright specs. Run `npm install`, `npm test`, and
   `npm exec --workspace @ai-image-editor/api -- wrangler deploy --dry-run`.
   Report actual results and any environment blockers. On an application
   failure, follow the existing `.pipeline/code-bug.md` handoff; the Test
   writer must not change application code or weaken assertions to pass.

## Done when

- Playwright installed; `npm test` runs all tests (Playwright config
  starts `npm run dev` as the web server).
- Test: with the default look, the rendered output matches the original.
- Test: exposure up raises mean brightness; red saturation changes
  reds far more than blues.
- Test: uploading a non-image shows a friendly message, no crash.
- Test: no network request carries image data.
